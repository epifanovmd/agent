# Стенд: бэкенд, агент, воркеры, сквозные тесты

Рабочий пример целиком:

- **бэкенд на Python** — сторона бэкенда протокола и небольшой HTTP API, только стандартная
  библиотека;
- **агент** — сам подключается к бэкенду и запускает **воркеры-примеры** на Python (без библиотек)
  и Go (пакет `worker`);
- **сквозные тесты** — настоящий агент с этими воркерами и бэкенд в процессе теста.

Протокол — [docs/PROTOCOL.md](../docs/PROTOCOL.md); устройство агента —
[docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md).

```
examples/
├── server/server.py       бэкенд стенда: протокол (часть I) и HTTP API (описан в docstring)
├── workers/
│   ├── echo/main.py       Python, только стандартная библиотека
│   └── sysinfo/main.go    Go, клиент github.com/epifanovmd/agent/worker
└── agent.demo.yaml        настройки агента стенда
```

## Воркеры

Оба — HTTP-клиенты сокета агента (`AGENT_SOCKET`, токен `AGENT_WORKER_TOKEN`): регистрируются с
манифестом (`POST /register`), держат поток `GET /stream` (желаемое, команды, отмена), присылают
итоги, ход, события и пульс раз в 10 с (`POST /health`).

| Воркер    | Настройка                                                        | Команды                                                                          | События, запросы                          | Метрики в пульсе               |
| --------- | ---------------------------------------------------------------- | -------------------------------------------------------------------------------- | ----------------------------------------- | ------------------------------ |
| `echo`    | `settings`: `{ prefix, upper }`; неверное значение — `ok: false` | `echo.say { text, lookup? }`, `echo.long { steps, delayMs, text? }`, `echo.hang` | событие `echo.said`, запрос `echo.lookup` | счётчики команд                |
| `sysinfo` | `banner`: `{ text }` (до 200 символов)                           | `sys.info` — процесс, узел, версия, баннер                                       | событие `sys.started`                     | горутины, память, время работы |

- **`echo.say`** — текст с префиксом из настройки; `lookup: true` — префикс воркер спрашивает у
  бэкенда запросом `echo.lookup` (бэкенд стенда отвечает `<имя агента>: `).
- **`echo.long`** — долгая команда по шагам: ход (`POST /progress`) после каждого шага, пока идёт —
  пульс `busy: true`, и агент откладывает плановый перезапуск и обновление воркера; отмена — итог
  `CANCELLED`.
- **`echo.hang`** — воркер перестаёт присылать пульс, и агент его перезапускает.
- Метрики узла агент собирает сам; метрики воркеров из пульса идут бэкенду вместе с ними.

## Запуск

Нужны python3 и Docker. Go ставить не нужно — он запускается в контейнере.

```bash
make demo-build          # один раз: агент и sysinfo → .dev/bin
make demo-server         # бэкенд: http://localhost:8080 (токен регистрации demo-token)
make demo-agent          # в другом терминале: агент demo-1 с воркерами echo и sysinfo
scripts/demo.sh agent 2  # ещё один агент (свой каталог данных .dev/demo-agent-2)
scripts/demo.sh status   # состояние агента 1: связь, воркеры, последняя ошибка
```

Агент стенда ходит к бэкенду по `http://` — это разрешает `server.allowInsecure: true` в
`agent.demo.yaml`; на узлах — только `https://`. Другой порт — `PORT=8081` для `server` и `agent`;
токен — `DEMO_TOKEN` (один для бэкенда и агента); адрес бэкенда для агента — `AGENT_SERVER_URL`
(по умолчанию `http://localhost:$PORT`).

### HTTP API бэкенда

Всё — JSON. Подробно — docstring [server/server.py](server/server.py).

| Запрос                                                  | Что                                                                       |
| ------------------------------------------------------- | ------------------------------------------------------------------------- |
| `GET /api/agents`                                       | агенты: id, имя, связь, версия                                            |
| `GET /api/agents/{id}`                                  | всё об агенте: `hello`, `state`, `desired`                                |
| `PUT`, `DELETE /api/agents/{id}/configs/{worker}/{key}` | задать (тело — значение) или удалить ключ настроек: новая версия и `rev`  |
| `PUT`, `DELETE /api/agents/{id}/watch`                  | наблюдение `{ metricsIntervalMs, logLevel, until }` или снять его         |
| `POST /api/agents/{id}/commands?wait=30`                | команда агенту `{ type, args, deadline? }`; `wait` — ждать итога, с       |
| `POST /api/agents/{id}/workers/{worker}/command`        | команда воркеру `{ type, args, timeoutMs? }` → итог                       |
| `GET /api/agents/{id}/commands/{cid}`                   | команда и её итог                                                         |
| `GET /api/agents/{id}/events`, `metrics`, `logs`        | события воркеров, точки метрик, записи журнала — новые первыми, `?limit=` |
| `POST /api/agents/{id}/revoke`                          | отозвать агента                                                           |

```bash
curl -s localhost:8080/api/agents                                                   # агенты, их id
curl -X PUT localhost:8080/api/agents/<id>/configs/echo/settings -d '{"prefix":"> "}'
curl -X POST localhost:8080/api/agents/<id>/workers/echo/command -d '{"type":"echo.say","args":{"text":"привет"}}'
curl -X POST 'localhost:8080/api/agents/<id>/commands?wait=10' -d '{"type":"agent.logs","args":{"worker":"echo"}}'
```

| Переменная бэкенда    | По умолчанию       | Что                                   |
| --------------------- | ------------------ | ------------------------------------- |
| `PORT`                | `8080`             | порт                                  |
| `ENROLL_TOKEN`        | `demo-token`       | токен регистрации агентов             |
| `DATA_FILE`           | `.dev/server.json` | файл состояния: переживает перезапуск |
| `TLS_CERT`, `TLS_KEY` | —                  | сертификат и ключ — HTTPS вместо HTTP |

Ограничения примера: у API нет авторизации, одна копия бэкенда, состояние — в памяти и в одном
файле. Настоящий бэкенд хранит агентов, желаемое, команды и события в своей базе (§21 протокола) и
проверяет, кто делает запрос.

### Без бэкенда

С `server.required: false` (`AGENT_SERVER_REQUIRED=false`) агент работает и без `server.url`:
желаемое — из файлов `desired/<воркер>/<ключ>.json` рядом с `agent.yaml` (перечитываются по
`SIGHUP`), команды — через локальный API:

```bash
agent command echo echo.say '{"text":"привет"}'
```

## Сквозные тесты

```bash
make e2e   # test/e2e, тег сборки e2e: около минуты
```

Тесты собирают агента и `sysinfo`, поднимают бэкенд в процессе теста (`test/e2e/backend_test.go`,
всё в памяти) и настоящий агент с воркерами `echo` и `sysinfo` во временном каталоге.

| Тест                    | Что проверяет                                                                                                                      |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `TestHelloStateMetrics` | регистрация по токену, `hello` с манифестами воркеров, состояние, метрики узла и воркеров, журнал                                  |
| `TestDesiredConfigs`    | настройка доходит до воркера, итог применения — в состоянии; неверное значение — `ok: false`; ключ не из манифеста — ошибка        |
| `TestWorkerCommands`    | итог, событие, запрос к бэкенду; ход и отмена долгой команды; `COMMAND_UNDECLARED`, `WORKER_UNKNOWN`; повтор команды с тем же `id` |
| `TestAgentCommands`     | журнал, перезапуск воркера, смена ключа, обновление при `update.mode: disabled`                                                    |
| `TestAgentRestart`      | воркеры переживают перезапуск агента; долгая команда завершается с итогом; ключ и `seq` сохраняются                                |
| `TestOutboxOffline`     | без связи события копятся на диске и доходят, когда бэкенд снова доступен, — и через перезапуск агента                             |
| `TestPollFallback`      | поток буферизуется — агент переходит на длинный опрос и получает команды                                                           |
| `TestReenrollAndRevoke` | ключ не известен — регистрация заново по токену; отозванный агент прекращает связь, воркеры работают                               |
| `TestWithoutBackend`    | желаемое из файлов `desired/`, перечитывание по `SIGHUP`, команды через локальный API                                              |
| `TestWorkerUpdate`      | `worker.update`: подписанная сборка заменяет воркер; неверная подпись — `UPDATE_FAILED`, воркер на прежней сборке                  |
