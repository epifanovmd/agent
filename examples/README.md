# Стенд: сервер, веб-интерфейс, воркеры

Рабочий пример целиком:

- **сервер на Node.js** — небольшой бэкенд на `agent-sdk/server`;
- **агент** — сам подключается к серверу и запускает **воркеры** на Python, Go и Node.js;
- **веб-интерфейс** на React — показывает всё вживую и проверяет каждый воркер.

Есть и такой же сервер на Python — [server-python](server-python/README.md). Как работает SDK —
[sdk/docs](../sdk/docs/README.md).

```
examples/
├── server/              бэкенд на agent-sdk/server (TypeScript через tsx, без сборки)
│   ├── src/main.ts      создание `Agents`, переменные окружения
│   ├── src/app.ts       API для интерфейса (API.md), WebSocket /api/ws и раздача интерфейса
│   └── test/            тесты API с поддельным агентом (node --import tsx --test)
├── server-python/       тот же бэкенд на agent_sdk.server, только стандартная библиотека
├── web/                 интерфейс (React + Vite)
│   ├── src/selfcheck.ts проверки воркеров (в интерфейсе и в терминале)
│   └── selfcheck.cli.ts самопроверка из терминала
├── workers/
│   ├── echo_worker.py   Python: очередь example.echo — текст, входной и выходной файлы, повторы
│   ├── batch_worker.py  Python: пакетная обработка example.batch — этапы, событие stage, досрочная
│   │                    остановка, файл-результат, команда example.batch.status, показатели
│   ├── kv_worker.py     Python: хранилище ключей — состояние example.kv, команда, показатели, события,
│   │                    здоровье (не в порядке, пока каталог не удаётся привести к снимку)
│   ├── sysinfo/main.go  Go (sdk/go/worker): команды (с выводом по мере работы), состояние
│   │                    example.sys.banner, показатели, событие
│   └── node/main.ts     Node.js: очередь example.hash (sha256 файла, прогресс, файл-результат),
│                        команды example.node.info/fail/health, состояние example.node.config
│                        (настройки воркера), показатели, события, здоровье
├── docker/              Dockerfile сервера (с выпуском агента) и агента (с воркерами)
├── agent.demo.yaml      настройки агента для стенда: сервер и пять воркеров
├── docker-compose.yml   стенд в Docker
└── API.md               API бэкендов стенда для интерфейса
```

## Запуск в Docker

Нужен только Docker:

```bash
docker compose -f examples/docker-compose.yml up --build                  # http://localhost:8080
docker compose -f examples/docker-compose.yml up --build --scale agent=3  # три агента
DEMO_PORT=8081 docker compose -f examples/docker-compose.yml up --build   # если 8080 занят → http://localhost:8081
```

Образ сервера содержит и выпуск агента (linux/darwin × amd64/arm64). Поставить агента на другую
машину с Linux и systemd:

```bash
curl -fsSL http://<адрес>:8080/api/v1/agent-link/install.sh | sudo sh -s -- --token demo-token
```

Порт 8080 занимает и `make demo-server`. Если он запущен, поднимайте Docker-стенд на другом
порту (`DEMO_PORT`) или остановите локальный сервер.

## Запуск без Docker

Нужны Node ≥ 24 и python3. Go ставить не нужно — он запускается в контейнере.

`make demo-build` собирает агента и Go-воркер под эту машину в `.dev/bin`, выпуск агента в
`dist/<VERSION>` (`scripts/release.sh`: сборки, `manifest.json`, `install.sh`), SDK для Node,
ставит зависимости и собирает интерфейс. Данные агентов стенда — в `.dev/demo-agent-<N>`.

```bash
make demo-build     # сборка — один раз
make demo-server    # сервер и интерфейс: http://localhost:8080 (токен регистрации demo-token)
make demo-agent     # в другом терминале: агент demo-1 с пятью воркерами
scripts/demo.sh agent 2                      # ещё один агент
AGENT_TRANSPORT=http scripts/demo.sh agent 3 # агент только через HTTP — как за прокси без WebSocket
make demo-check     # самопроверка из терминала (код выхода 1 — есть ошибки)
```

Разработка интерфейса с автообновлением: `cd examples/web && npm run dev` →
http://localhost:5173. Запросы к API уходят на сервер :8080 (адрес меняет `DEMO_SERVER`).

## Что есть в интерфейсе

| Вкладка      | Что там                                                                                                                                                                                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Агенты       | выпуск агента и кнопка «Обновить», команда установки; на связи ли агент, как подключён, процессор, память, сеть; его воркеры (состояние, здоровье, пауза, кнопки «Пауза» и «Продолжить»), очереди, команды, состояние, показатели; «Графики и сведения»; «Отозвать» |
| Задачи       | поставить задачу (`example.echo`, `example.batch`, `example.hash`), смотреть прогресс, журнал, события, результат, файлы; остановить или отменить                                                                                                                   |
| Команды      | любая объявленная команда на любом или выбранном агенте: вывод по мере работы, итог, ошибка с кодом                                                                                                                                                                 |
| Состояние    | задать состояние (`example.kv`, `example.sys.banner`, `example.node.config`) всем агентам или одному, вернуть агента на общее состояние («Вернуть общее») и посмотреть, как агенты его применили                                                                    |
| События      | события воркеров (`sys.started`, `kv.applied`, `node.started`, …)                                                                                                                                                                                                   |
| Самопроверка | проверка каждого воркера: задачи, повторы, остановка, отмена, состояние → команда, вывод, срок команды, показатели, события                                                                                                                                         |

**Воркеры на карточке агента** — состояние, число копий, версия и ещё:

- **здоровье** — `ok` или `degraded` с причиной, как воркер сам о себе сообщил (например, `kv`
  не может записать каталог). Пока воркер не в порядке, агент тоже `degraded`, а в списке
  проблем есть `workerDegraded`;
- **пауза** — «на паузе», если хоть одна очередь воркера не берёт новые задачи. Кнопки «Пауза» и
  «Продолжить» отправляют команды `worker.pause` и `worker.resume`. «Продолжить» снимает только
  паузу сервера: паузу, которую поставил сам воркер, снимает только он.

**Графики** — кнопка «Графики и сведения» на карточке агента. Графики идут по группам метрик
узла — есть данные группы, есть и график:

- процессор, нагрузка (load average), память, swap;
- диск `/` и другие файловые системы из `telemetry.disks`, чтение и запись дисков;
- сеть: приём и отдача, всего или по выбранному интерфейсу; ошибки и отброшенные пакеты;
- TCP-соединения, процессы и потоки, температура;
- видеокарты, если есть;
- окно 15 минут или 1 час;
- ниже — показатели воркеров и лог агента и воркеров с выбранного уровня.

При открытии интерфейс берёт историю с сервера, а дальше подписывается на агента через
WebSocket `/api/ws`. Пока карточка открыта, бэкенд держит подписку на агента: метрики и
показатели воркеров раз в секунду, дополнительные группы `diskio`, `sockets`, `processes`,
`temperatures` и лог с выбранного уровня. Каждая новая точка сразу появляется на графике.
Карточку закрыли — подписка снимается, и агент возвращается к обычной частоте. Точки, собранные
без связи и досланные позже, нарисованы бледным пунктиром.

**Сведения об узле** — ОС, виртуализация, процессор, память, диски, сетевые адреса, видеокарты,
открытые порты. Агент присылает их после подключения и при изменении.

**Обновления** — панель «Выпуск агента» над карточками:

- версия из `dist/<VERSION>` (её собирает `make demo-build`);
- агенты, у которых версия другая и которые умеют обновляться сами;
- кнопка «Обновить».

Выпуск без `AGENT_SIGNING_KEY` не подписан, и агент такое обновление отклонит. Подписанный
выпуск: `AGENT_SIGNING_KEY=… make release` и `PUBLIC_KEY=<открытый ключ> make demo-server`. Агенты
стенда сами не обновляются (`update.mode: disabled` в `agent.demo.yaml`) — обновление проверяют на
агенте, поставленном через `install.sh`.

**Установка одной командой** — в той же панели, с кнопкой «Копировать»:

```bash
curl -fsSL http://<сервер>/api/v1/agent-link/install.sh | sudo sh -s -- --token demo-token
```

**Отозвать** — сервер перестаёт принимать этого агента: ему нужна новая регистрация.

### Что попробовать

- Замените воркер командой `worker.restart` с `{"name": "kv"}` — простоя не будет.
- Поставьте воркер `echo` на паузу кнопкой «Пауза» и поставьте задачу `example.echo` на этот
  агент — она будет ждать, пока не нажмёте «Продолжить».
- Выполните команду `example.node.health` с `{"ok": false, "message": "проверка"}` — воркер `node`
  и агент станут `degraded`, появится проблема `workerDegraded`.
- Остановите сервер — агенты переподключатся сами. Итоги задач, завершённых без связи, придут
  после подключения.
- Поменяйте состояние `example.kv`, пока агент выключен, — он применит его, когда подключится.

## Свой воркер

Воркер говорит, что умеет, и агент делает это доступным серверу. Ни агента, ни сервер для
этого менять не нужно.

- **Python** — `agent_sdk.worker` ([sdk/python](../sdk/python/README.md)): `@worker.job`,
  `@worker.command`, `@worker.state`, `@worker.telemetry`, `worker.event`, `worker.set_health`. Пример —
  [workers/kv_worker.py](workers/kv_worker.py).
- **Node.js** — `agent-sdk/worker`: `worker.job`, `worker.command`, `worker.state`,
  `worker.telemetry`, `worker.event`, `worker.setHealth`, отмена через `job.signal`. Пример —
  [workers/node/main.ts](workers/node/main.ts); SDK и зависимости ставит `make demo-build`, запуск —
  `node --import tsx main.ts` из каталога воркера.
- **Go** — `sdk/go/worker`: `w.Job`, `w.Command`, `w.State`, `w.Telemetry`, `w.Event`. Пример —
  [workers/sysinfo/main.go](workers/sysinfo/main.go).
- **Без SDK** — строки JSON через дескриптор `AGENT_IPC_FD`, формат — §10
  [sdk/spec](../sdk/spec/README.md).

Затем добавьте воркер в `workers` настроек агента (как в [agent.demo.yaml](agent.demo.yaml)); все
поля — в [docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md#настройки).

## Сервер — пример, а не готовый продукт

Всё, что связано с агентами, делает `Agents` из `agent-sdk/server`. Пример добавляет только API для
интерфейса (`src/app.ts`, полностью — [API.md](API.md)).

Переменные сервера:

| Переменная                                  | По умолчанию                            | Что                                                                 |
| ------------------------------------------- | --------------------------------------- | ------------------------------------------------------------------- |
| `PORT`                                      | `8080`                                  | порт                                                                |
| `ENROLL_TOKEN`                              | `demo-token`                            | токен регистрации агентов                                           |
| `RELEASES_DIR`                              | `dist/<VERSION>` (в `make demo-server`) | каталог выпуска агента; без него нет обновлений и `install.sh`      |
| `PUBLIC_KEY`                                | —                                       | открытый ключ проверки подписи (base64), вписывается в `install.sh` |
| `STATUS_INTERVAL_MS`, `METRICS_INTERVAL_MS` | `5000`                                  | как часто агенты шлют статус и метрики                              |
| `METRICS_STORE_INTERVAL_MS`                 | `5000`                                  | как часто точка метрик попадает в историю (`0` — каждая)            |
| `WEB_DIR`                                   | `examples/web/dist`                     | собранный интерфейс                                                 |

Ограничения примера:

- всё хранится в памяти (`MemoryStore`, `MemoryFiles`);
- у API нет авторизации;
- ссылки на файлы не подписаны.

Настоящий бэкенд передаёт `Agents` свой `Store` (БД) и свой `files` с подписанными ссылками.
