# Как вносить изменения

Что это за проект и как он устроен — [README.md](README.md) и
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Здесь — правила разработки.

## Окружение

- Go ставить не нужно: цели `make` запускают его в контейнере `golang` (`scripts/go.sh`), нужен
  Docker.
- Node ≥ 24 и python3 (≥ 3.10) — на машине.
- Список целей — `make help`, стенд для ручной проверки — [examples/README.md](examples/README.md).

## Перед коммитом

```bash
make check
```

Это `vet`, `fmt-check` (gofmt), `format-check` (Prettier), `version-check`, `race`, `sdk-test`,
`examples-test`. Всё должно проходить без замечаний. Отформатировать код — `make fmt` (Go) и
`make format` (всё остальное).

## Правила

**Спецификация — источник правды.** Формат сообщений меняется в таком порядке:

1. [sdk/spec/README.md](sdk/spec/README.md) и образцы сообщений `sdk/spec/examples` — файлы по
   темам (`connection.json`, `observe.json`, `jobs.json`, `commands.json`, `state.json`,
   `events.json`, `workers.json`), в каждом объект «имя образца → `{from, to, message}`»; ключи
   для запечатанных значений — `sealed.json`. Новый тип сообщения или новое поле — новый или
   дополненный образец в файле своей темы;
2. типы сообщений `sdk/go/message`;
3. SDK всех языков — `sdk/go`, `sdk/node`, `sdk/python` — с одинаковым поведением по
   [sdk/README.md](sdk/README.md) и [sdk/docs](sdk/docs/README.md);
4. общий тест серверов `test/conformance`.

Внутри версии формата — только добавления: новые необязательные поля, типы сообщений,
возможности. Несовместимое изменение — новая версия формата.

**Без знания о конкретных проектах.** В агенте, SDK, тестах и документации нет путей, имён
модулей и очередей конкретных проектов. Примеры — с префиксом `example.` (`example.echo`,
`example.app`).

**Агент один на все проекты.** Своей сборки агента под проект нет: возможности добавляются
воркерами. `internal/` — устройство агента, его можно менять свободно. Публичное API — только SDK
(`sdk/go/*`, `agent-sdk`, `agent_sdk`), его меняем осторожно и одинаково во всех языках.

**Кто за что отвечает.** Связь, очередь важных сообщений, повторы, ключ агента, обновление — в
агенте; воркер (и SDK воркера) знает только свою предметную область. На сервере работу со связью
делает `Agents` из серверного SDK — бэкенды и примеры её не повторяют.

**Остановка и ошибки.** Остановка — через `context` (в Node — `AbortSignal`, в Python —
`threading.Event`). Паника или исключение в обработчике — ошибка задачи или команды, а не падение
агента или воркера.

**Тесты.**

- Новое поведение — с тестом.
- Исправление ошибки — сначала тест, который её воспроизводит, потом исправление.
- Сквозное поведение агента — тест в `test/integration` (настоящий агент против сервера на Go-SDK,
  `test/testserver`).
- Поведение серверной части SDK — общий сценарий в `test/conformance`: один и тот же для Go, Node
  и Python.

**Код.**

- Лог агента — `log/slog` (через `internal/logx`).
- Комментарии — по-русски, кратко: к публичным контрактам и неочевидным местам.

**Документация.**

- Простым языком, без жаргона и заумных названий. Словарь понятий — в [README.md](README.md).
- Имена полей, типов сообщений, команд и опций не переводятся, а поясняются.
- Каждый документ отвечает за своё и не повторяет другие: README — обзор и команды, ARCHITECTURE —
  устройство агента, настройки и установка, sdk/docs — подключение по шагам и описание SDK (с
  чего начать — [sdk/docs/README.md](sdk/docs/README.md)), sdk/spec — формат сообщений,
  examples — стенд.
- Документы описывают то, что есть в коде сейчас. Поменяли опцию, флаг, команду — поправьте
  документ в том же изменении.

## Версия и выпуск

Версия одна на агента, все SDK и примеры — файл `VERSION`. Новая версия — `make version V=1.2.0`;
`make version-check` (и `make check`) проверяет, что она везде одинаковая. Выпуск публикует CI по
тегу `v<VERSION>` — подробнее в [README.md](README.md#выпуск).

Об уязвимостях — не в открытых issue, а закрыто: [SECURITY.md](SECURITY.md).
