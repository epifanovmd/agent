# Как вносить изменения

Что это за проект и как он устроен — [README.md](README.md) и
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Здесь — правила разработки.

## Окружение

- Go ставить не нужно: цели `make` запускают его в контейнере `golang` (`scripts/go.sh`), нужен
  Docker.
- Node ≥ 24 и python3 (стенд и сквозные тесты) — на машине.
- Список целей — `make help`, стенд для ручной проверки — [examples/README.md](examples/README.md).

## Перед коммитом

```bash
make check
```

Это `vet`, `fmt-check` (gofmt), `format-check` (Prettier), `version-check`, `race`, `sdk-test`,
`examples-test`, `e2e` (нужен python3). Всё должно проходить без замечаний. Отформатировать код — `make fmt` (Go) и
`make format` (всё остальное).

## Правила

**Спецификация — источник правды.** Формат сообщений меняется в таком порядке:

1. [sdk/spec/README.md](sdk/spec/README.md) и образцы `sdk/spec/examples` — файлы по темам
   (`connection.json`, `configs.json`, `fetch.json`, `observe.json`, `actions.json`,
   `events.json` — сообщения WebSocket; `worker.json` — HTTP между агентом и воркером). Новый тип
   сообщения или новое поле — новый или дополненный образец в файле своей темы;
2. типы сообщений агента `internal/message` (их проверяют на всех образцах);
3. серверный SDK `agent-sdk` (`sdk/node`) и его описание — [sdk/README.md](sdk/README.md) и
   [sdk/docs](sdk/docs/README.md);
4. сквозные тесты агента `test/integration`.

Внутри версии формата — только добавления: новые необязательные поля и типы сообщений.
Несовместимое изменение — новая версия формата.

**Без знания о конкретных проектах.** В агенте, SDK, тестах и документации нет путей, имён и
предметных областей конкретных проектов. Примеры — с префиксом `example.` (`example.done`,
`api.example.com`).

**Агент один на все проекты.** Своей сборки агента под проект нет: возможности добавляются
воркерами. Агент — труба: он передаёт запросы, настройки, события и метрики, не разбирая их.
Воркер — HTTP-сервис на unix-сокете на любом языке, без SDK; что он обслуживает и что даёт ему
агент — §12 спецификации. `internal/` — устройство агента, его можно менять свободно. Публичное
API — формат связи и серверный SDK `agent-sdk`, их меняем осторожно.

**Кто за что отвечает.** Связь, очередь важных сообщений (outbox), повторы, ключ агента,
настройки воркеров на диске, обновление — в агенте; воркер знает только свою предметную область.
На сервере работу со связью делает `Agents` из серверного SDK — бэкенды и стенд её не повторяют.

**Тесты.**

- Новое поведение — с тестом.
- Исправление ошибки — сначала тест, который её воспроизводит, потом исправление.
- Поведение серверного SDK — тесты `sdk/node/test`.
- Сквозное поведение агента — тест в `test/integration`: настоящий агент против сервера на
  `agent-sdk/server` (`test/testserver`, процесс node), воркеры — простые HTTP-серверы на Go в
  самом тесте. Тестам нужен собранный `sdk/node` (`make test` собирает его сам); без node тест
  пропускается, в CI — падает.
- Сценарии целиком — сквозные тесты стенда `examples/server/e2e` (`make e2e`): сервер стенда на
  `agent-sdk/server` в процессе теста, настоящий агент и воркеры-примеры на Python, Node.js и Go.
  Новая возможность, заметная пользователю стенда, — со сценарием там.

**Код.**

- Лог агента — `log/slog` (через `internal/logx`).
- Остановка — через `context`.
- Комментарии — по-русски, кратко: к публичным контрактам и неочевидным местам.

**Код серверного SDK** (`sdk/node`; тот же стиль и те же файлы настроек — у сервера стенда
`examples/server`).

- Стиль — ESLint (`sdk/node/eslint.config.mjs`) и Prettier (`sdk/node/.prettierrc.json`: ширина
  строки 80, двойные кавычки, запятые в конце, стрелки без скобок у одного параметра). Проверка —
  `npm run lint` и `npm run format:check`, исправление — `npm run lint:fix` и `npm run format`;
  корневые `make format` и `make format-check` берут этот же файл настроек.
- Функции — стрелочные выражения (`const f = () => …`), импорты отсортированы, без `console`
  (журнал — опция `log`), без `++`/`--` и битовых операций, без `any`.
- Слои — только вниз, без циклов (`npx madge --circular --extensions ts src`): `agents.ts` →
  `features/` → `transport/` → `core/` → `store/` → `model/` → `protocol/`, `lib/`.
- Входящие данные проверяются схемами `zod` в `protocol/schemas.ts`; типы сообщений выводятся из
  схем (`z.output`), проверка с причиной отказа по-русски — `protocol/checks.ts`. Пределы и
  правила имён — постоянные `protocol/constants.ts`. Незнакомые поля в сообщениях агента
  пропускаются.
- Версии сравниваются по semver (`lib/version.ts`).

**Документация.**

- Простым языком, без жаргона и заумных названий. Словарь понятий — в [README.md](README.md).
- Имена полей, типов сообщений, команд и опций не переводятся, а поясняются.
- Каждый документ отвечает за своё и не повторяет другие: README — обзор и команды, ARCHITECTURE —
  устройство агента, настройки и установка, sdk/docs — подключение по шагам и описание SDK (с
  чего начать — [sdk/docs/README.md](sdk/docs/README.md)), sdk/spec — формат сообщений,
  examples — стенд.
- Документы описывают то, что есть в коде сейчас. Поменяли опцию, флаг, команду — поправьте
  документ в том же изменении.

## Версия и выпуск

Версия одна на агента, SDK и примеры — файл `VERSION`. Новая версия — `make version V=1.2.0`;
`make version-check` (и `make check`) проверяет, что она везде одинаковая. Выпуск публикует CI по
тегу `v<VERSION>` — подробнее в [README.md](README.md#выпуск).

Об уязвимостях — не в открытых issue, а закрыто: [SECURITY.md](SECURITY.md).
