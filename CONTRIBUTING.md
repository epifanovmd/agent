# Как вносить изменения

Что это за проект и как он устроен — [README.md](README.md) и
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Здесь — правила разработки.

## Окружение

- Go ставить не нужно: цели `make` запускают его в контейнере `golang` (`scripts/go.sh`), нужен
  Docker.
- python3 — на машине (стенд); в контейнере для тестов он уже есть.
- Список целей — `make help`, стенд для ручной проверки — [examples/README.md](examples/README.md).

```
cmd/agent/    программа агента
internal/     устройство агента — docs/ARCHITECTURE.md
protocol/     типы и константы протокола (публичный пакет)
worker/       клиент воркера на Go (публичный пакет)
docs/         протокол (PROTOCOL.md) и устройство агента (ARCHITECTURE.md)
examples/     стенд: бэкенд на Python, воркеры-примеры, agent.demo.yaml
test/e2e/     сквозные тесты: настоящий агент, воркеры-примеры, бэкенд в процессе теста
deploy/       образы Docker, install.sh
scripts/      Go в контейнере, стенд, версия, сборки
```

## Перед коммитом

```bash
make check
```

Это `vet`, `fmt-check` (gofmt), `version-check`, `race`, `examples-test` (синтаксис примеров на
Python) и `e2e`. Всё должно проходить без замечаний. Отформатировать Go-код — `make fmt`.

## Правила

**Протокол — источник правды.** Формат связи меняется в таком порядке:

1. [docs/PROTOCOL.md](docs/PROTOCOL.md) — маршруты, сообщения, коды ошибок, пределы;
2. типы и константы — пакет `protocol`;
3. агент (`internal/`) и клиент воркера — пакет `worker`;
4. примеры (`examples/server/server.py`, `examples/workers`) и бэкенд сквозных тестов
   (`test/e2e/backend_test.go`).

Внутри версии протокола — только добавления: новые необязательные поля, типы команд и событий.
Несовместимое изменение — новая версия протокола (`/agent/v2`).

**Без знания о конкретных проектах.** В агенте, тестах и документации нет путей, имён и
предметных областей конкретных проектов. Примеры — с префиксом `example.` (`example.done`,
`api.example.com`).

**Агент один на все проекты.** Своей сборки агента под проект нет: возможности добавляются
воркерами. Агент — труба: он передаёт желаемое, команды, итоги, события и метрики, не разбирая их
содержимое; схемы в манифесте воркера проверяет бэкенд. Воркер — HTTP-клиент сокета агента на
любом языке; пакет `worker` — удобство для Go, а не обязательная библиотека. `internal/` —
устройство агента, его можно менять свободно. Публичное API — протокол и пакеты `protocol` и
`worker`, их меняем осторожно.

**Кто за что отвечает.** Связь, очередь на диске (outbox), повторы, ключ агента, хранение
желаемого, надзор за воркерами, метрики узла, обновление — в агенте; воркер знает только свою
предметную область; бэкенд решает, что и кому поручить.

**Тесты.**

- Новое поведение — с тестом.
- Исправление ошибки — сначала тест, который её воспроизводит, потом исправление.
- Модульные тесты — рядом с кодом (`make test`, `make race`).
- Сквозное поведение — тест в `test/e2e` (`make e2e`, тег сборки `e2e`): настоящий агент, воркеры
  `echo` (Python) и `sysinfo` (Go), бэкенд в процессе теста. Новая возможность протокола — со
  сценарием там.

**Код.**

- Лог агента — `log/slog` (через `internal/logx`).
- Остановка — через `context`.
- Комментарии — по-русски, кратко: к публичным контрактам и неочевидным местам.
- Примеры на Python — только стандартная библиотека.

**Документация.**

- Простым языком, без жаргона и заумных названий.
- Имена полей, типов сообщений, команд и опций не переводятся, а поясняются.
- Каждый документ отвечает за своё и не повторяет другие: README — обзор и команды, PROTOCOL —
  протокол, ARCHITECTURE — устройство агента, настройки и установка, examples — стенд.
- Документы описывают то, что есть в коде сейчас. Поменяли опцию, флаг, команду или маршрут —
  поправьте документ в том же изменении.

## Версия и публикация

Версия агента — файл `VERSION`. Новая версия — `make version V=1.2.0`; `make version-check` (и
`make check`) проверяет её вид.

**Публикация.** Тег `v<VERSION>` → CI выкладывает в GitHub Release подписанные сборки агента,
`manifest.json`, `install.sh` и образы `ghcr.io/epifanovmd/agent:<версия>`, `:<версия>-python`,
`ghcr.io/epifanovmd/agent-dist:<версия>`. Ключ подписи — секрет репозитория `AGENT_SIGNING_KEY`,
открытый ключ — переменная `AGENT_UPDATE_PUBLIC_KEY` (CI вшивает его в агента).

Об уязвимостях — не в открытых issue, а закрыто: [SECURITY.md](SECURITY.md).
