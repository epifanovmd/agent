# agent

**Агент** — программа, которая ставится на каждый сервер (виртуальную машину, контейнер) и
держит связь с вашим бэкендом. **SDK** — библиотеки на Go, Node.js и Python, чтобы писать
бэкенд и воркеры для агента.

Агент один и тот же для всех проектов. Сам он умеет только общее:

- подключаться к серверу и переподключаться после обрыва;
- работать без связи, а потом досылать накопленное;
- присылать состояние узла и графики нагрузки (процессор, память, сеть, диск, видеокарты и
  другое — набор настраивается), чаще и подробнее — пока на узел смотрят;
- обновлять себя, проверяя подпись, и откатываться, если новая версия не запустилась.

Всё, что нужно конкретному проекту, делают **воркеры** — отдельные программы на любом языке,
которые агент запускает рядом с собой. Воркер говорит агенту, что он умеет, а агент
связывает это с сервером. Агент **ничего не знает о конкретных серверах**: сервер — любой
бэкенд на SDK.

## Словарь

| Слово             | Что это                                                                                                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **узел**          | машина, на которой работает агент                                                                                                                                                          |
| **воркер**        | программа проекта, которую агент запускает на узле; у воркера может быть несколько копий (экземпляров)                                                                                     |
| **задача**        | работа из очереди сервера: агент берёт её, воркер выполняет, результат уходит на сервер                                                                                                    |
| **команда**       | действие «сделай сейчас» на конкретном узле, с ответом                                                                                                                                     |
| **состояние**     | как всё должно быть на узле («такой список пользователей», «такие настройки»). Сервер присылает его целиком, воркер приводит узел к нему. Делится на разделы — по одному на каждую область |
| **группа метрик** | набор метрик узла, которые собираются вместе: `cpu`, `memory`, `disk`, `diskio`, `sockets` и другие; какие собирать — решает настройка агента                                              |
| **показатели**    | цифры воркера, которые приходят вместе с метриками узла (например, число подключений)                                                                                                      |
| **подписка**      | просьба бэкенда к агенту «присылай это чаще и подробнее, столько времени» — например, пока узел открыт в интерфейсе: статус и метрики чаще, больше групп метрик, подробнее лог             |
| **событие**       | сообщение воркера серверу «что-то случилось»                                                                                                                                               |
| **выпуск**        | подписанные сборки агента (и при желании воркеров) с `manifest.json`; бэкенд раздаёт их для установки и обновления                                                                         |
| **Agents**        | главный объект SDK для бэкенда — «все подключённые агенты»: принимает агентов, раздаёт задачи и команды, доставляет состояние                                                              |

## Быстрый старт

Весь стенд — бэкенд, интерфейс, агент с пятью воркерами и самопроверка:

```bash
docker compose -f examples/docker-compose.yml up --build    # http://localhost:8080
```

Без Docker (нужны Node ≥ 24 и python3; Go ставить не нужно, он запускается в контейнере):

```bash
make demo-build     # собрать агента, Go-воркер, выпуск агента, SDK для Node, интерфейс
make demo-server    # терминал 1 — http://localhost:8080
make demo-agent     # терминал 2 — агент с воркерами echo, batch, kv (Python), sysinfo (Go), node (Node.js)
make demo-check     # проверить все воркеры из терминала
```

Подробнее о стенде — [examples/README.md](examples/README.md).

## Команды

Go на машине не нужен: цели `make` запускают его в контейнере `golang` (`scripts/go.sh`).
Node ≥ 24 и python3 нужны на машине. Список целей — `make help`.

| Команда                | Что делает                                                                                                  |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- |
| `make test`            | тесты на Go: агент, Go-SDK, образцы сообщений, `test/integration`, `test/conformance`                       |
| `make race`            | то же с поиском гонок                                                                                       |
| `make vet`             | `go vet`                                                                                                    |
| `make fmt`             | отформатировать Go-код (gofmt)                                                                              |
| `make fmt-check`       | проверить форматирование Go-кода, ничего не меняя                                                           |
| `make format`          | Prettier на весь проект: TS/JS, JSON, YAML, Markdown, CSS                                                   |
| `make format-check`    | проверить Prettier, ничего не меняя                                                                         |
| `make tidy`            | `go mod tidy`                                                                                               |
| `make sdk-test`        | тесты SDK на Python и Node (для Node — ещё ESLint и проверка типов)                                         |
| `make examples-test`   | тесты бэкендов стенда, проверка типов Node-воркера, сборка интерфейса                                       |
| `make version V=1.2.0` | записать версию во все места                                                                                |

## Как подключить к своему проекту

Бэкенд создаёт объект `Agents` из серверной части SDK, воркеры пишутся на SDK воркера, агент
ставится на узел одной командой. С чего начать — [sdk/docs/README.md](sdk/docs/README.md): там
подключение по шагам, с примерами кода, и подробное описание SDK. Формат сообщений для тех, кто
работает без SDK, — [sdk/spec](sdk/spec/README.md).

## Выпуск

Версия одна на агента и все SDK: файл `VERSION`. Записать новую везде — `make version V=1.2.0`;
`make check` (и CI) проверяет, что она совпадает во всех местах.

Тег `v<VERSION>` → CI выкладывает в GitHub Release (тег с «-», например `v1.2.0-rc.1`, —
предварительный выпуск):

- подписанные сборки агента, `manifest.json`, `install.sh`;
- SDK: архив для Node (`agent-sdk-<версия>.tgz`) и пакет для Python
  (`agent_sdk-<версия>-py3-none-any.whl`);

и образы `ghcr.io/epifanovmd/agent:<версия>-python` и `ghcr.io/epifanovmd/agent-dist:<версия>`.
Всё ставится с GitHub, без npm и PyPI — команды установки в [sdk/docs](sdk/docs/README.md).

Подпись: `agent keygen` выдаёт пару ключей. Закрытый (`AGENT_SIGNING_KEY`) — секрет репозитория
для CI. Открытый (`AGENT_UPDATE_PUBLIC_KEY`) — переменная репозитория: CI вшивает его в сборки
агента, и они проверяют обновления без настройки; бэкенду он нужен в опции `publicKey`. Как
поставить агента прямо из GitHub Release — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#установка).

Об уязвимостях сообщайте не в открытых issue — см. [SECURITY.md](SECURITY.md).

## Требования

- Агент: Linux или macOS, amd64 или arm64. Установка службой — Linux с systemd (Debian/Ubuntu,
  RHEL/Fedora, SUSE и т. п.); без systemd (Alpine и другие) — в контейнере.
- SDK: Go ≥ 1.25, Node.js ≥ 24, Python ≥ 3.10 (без зависимостей).
- Разработка: Docker, Node ≥ 24, python3.
