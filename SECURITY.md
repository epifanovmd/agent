# Безопасность

## Как сообщить об уязвимости

Не пишите об уязвимости в открытом issue. Сообщите закрыто через GitHub Security Advisories:
вкладка **Security** репозитория → **Report a vulnerability**
(<https://github.com/epifanovmd/agent/security/advisories/new>).

Опишите, что не так, как это повторить и на какой версии (`agent version`, версия SDK). Ответ —
в том же обсуждении. Исправление выходит новым выпуском; после него уязвимость описывается
публично.

## Что входит

- агент (`cmd/agent`, `internal/`): связь с сервером, ключ агента, проверка подписи обновлений и
  откат, запуск воркеров и их ограничения, раскрытие запечатанных секретов;
- SDK на Go, Node.js и Python (`sdk/`): серверная часть (`Agents` — регистрация, ключи агентов,
  раздача выпуска и файлов задач), SDK воркера, запечатывание секретов;
- установщик `deploy/install/install.sh` и образы из `deploy/`;
- сборка и подпись выпуска (`scripts/release.sh`, `agent release-manifest`).

Не входит: стенд из `examples/` (он для проверки на своей машине, без защиты) и уязвимости в
зависимостях, которые уже исправлены в самой зависимости, — для них достаточно обычного issue или
обновления зависимости.

## Поддерживаемые версии

Исправления выходят для последнего выпуска. Обновляйтесь на него: агент — командой
`agent.update` с бэкенда или новым образом, SDK — новой версией из GitHub Release.
