# Безопасность

## Как сообщить об уязвимости

Не пишите об уязвимости в открытом issue. Сообщите закрыто через GitHub Security Advisories:
вкладка **Security** репозитория → **Report a vulnerability**
(<https://github.com/epifanovmd/agent/security/advisories/new>).

Опишите, что не так, как это повторить и на какой версии (`agent version`). Ответ — в том же
обсуждении. Исправление выходит в новой версии; после него уязвимость описывается публично.

## Что входит

- агент (`cmd/agent`, `internal/`): связь с бэкендом (HTTPS, вход по ключу агента), регистрация,
  ключ агента и его смена, проверка подписи обновлений и откат, запуск воркеров, сокет агента и
  токены воркеров, локальный API (`admin.sock`), хранилище `agent.db`;
- публичные пакеты `protocol` и `worker`;
- установка (`agent install`, `deploy/install/install.sh`) и образы из `deploy/`;
- сборки агента и их подпись (`scripts/release.sh`, `agent manifest`, `agent pack`).

Протокол и то, что в нём защищено, — [docs/PROTOCOL.md](docs/PROTOCOL.md) (§4, §5, §10, §12).

## Секреты на узле

- **Ключ агента** — `<dataDir>/credentials.json` (0600). Бэкенд хранит не секрет, а его хеш
  (`sha256`) и сравнивает за постоянное время; ключ меняется командой `agent.rotateKey`.
- **Желаемое состояние** (настройки воркеров) хранится в `<dataDir>/agent.db` открытым текстом —
  так воркеры получают его и без связи с бэкендом. Шифрования на диске нет: файл доступен только
  пользователю агента (0600, каталоги 0700). Защищайте `dataDir` правами, зашифрованным диском
  или томом и не выкладывайте его резервные копии туда, куда не выложили бы ключ агента.
- **Сокеты агента** — в `<dataDir>/run/`: сокет воркеров принимает только запросы с токеном
  воркера (`Authorization: Worker <token>`), локальный API `admin.sock` доступен только владельцу
  агента.
- **Журналы.** Агент не пишет в журнал значения настроек, `args` и итоги команд, `data` событий и
  запросов, токены и ключи, заголовок `Authorization` — только имена, версии, размеры и коды. Вывод
  воркера агент передаёт в журнал как есть: секреты, которые воркер печатает сам, — на совести
  воркера. Бэкенд тоже не должен писать в журнал `Authorization` и тело регистрации.
- **Связь** — только по `https://`. `http://` разрешает лишь `server.allowInsecure: true` (стенд,
  локальная сеть): ключ агента и данные идут открытым текстом, агент предупреждает об этом при
  запуске.
- **Обновления** ставятся только с подписью Ed25519, которая сходится с ключом, вшитым в агента, или
  ключом из `update.publicKey`, `update.publicKeys`; ключей нет — обновление отклоняется.

Не входит: стенд из `examples/` (он для проверки на своей машине, без защиты) и уязвимости в
зависимостях, которые уже исправлены в самой зависимости, — для них достаточно обычного issue или
обновления зависимости.

## Поддерживаемые версии

Исправления выходят для последней версии. Обновляйтесь на неё: агент — `agent upgrade` на узле,
командой `agent.update` с бэкенда или новым образом.
